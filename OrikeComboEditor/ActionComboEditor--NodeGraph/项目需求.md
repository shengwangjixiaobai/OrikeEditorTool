# Action Graph 动作控制与编辑系统需求文档

版本：V1.0


# 1. 项目概述


## 1.1 项目名称

Action Graph 动作控制与编辑系统


## 1.2 项目背景

在动作类游戏中，角色动作之间存在复杂的切换关系。

例如：

- 普通攻击可以在特定时间被闪避取消。
- 不同攻击动作之间存在连招衔接。
- 技能动作可以打断普通动作。
- 不同动作之间存在优先级竞争。
- 动作切换需要支持动画融合。


传统 Unity Animator 状态机主要用于动画状态切换，难以满足复杂动作游戏中的：

- 输入缓存
- 搓招检测
- 动作取消
- 动作预约
- 优先级竞争
- 自定义动画过渡


因此需要开发一套独立的：

**Action Graph + Action Controller + Transition System**

用于管理角色动作逻辑。

开发一套完整动作控制框架。


系统包括：

- Action逻辑系统
- ActionData表现系统
- ActionPlayer播放系统
- Cancel系统
- BeCancel系统
- KeyCommand输入系统
- Reservation Action预约系统
- ActionController动作控制系统
- Transition动画过渡系统
- Action Graph节点编辑器

运行时根据：

- 玩家输入

- 优先级

自动完成动作切换。

# 4. 已有系统说明


# 4.1 ActionData系统（已有）


ActionData只负责动作表现。


职责：

- 保存动画资源。
- 保存动画播放数据。
- 保存Timeline数据。
- 保存Track数据。


ActionData不包含：

- Cancel关系。
- BeCancel关系。
- 输入条件。
- 优先级。
- 动作切换逻辑。


ActionData本质：

> 一个动作的表现资源。

ActionPlayer负责播放ActionData。


职责：

- 播放动作动画。
- 控制动画时间。
- 设置动画播放位置。
- 执行动画混合。


ActionPlayer不负责：

- 判断动作切换。
- 判断输入。
- 判断Cancel。

Input系统负责：

- KeyCommand检测。

# 5. Action系统


# 5.1 Action定义


Action是真正参与游戏逻辑的动作对象。


Node节点对应Action。


Action负责：

- 管理动作逻辑。
- 引用ActionData。
- 保存Cancel关系。
- 保存BeCancel关系。
- 保存输入条件。
- 保存优先级。


---

# 5.2 Action数据结构


示例：


```csharp
Action

{

    string id;


    ActionData actionData;


    CancelData[] cancel;


    BeCancelData[] beCancel;


    KeyCommand[] keyCommands;


    TransitionData[] transitions;


    int priority;

}
```


---

# 6. Action与ActionData关系


Action负责：

"什么时候执行这个动作"


ActionData负责：

"执行时播放什么内容"


例如：

Action：

```
Attack01
```


引用：

```
Attack01_ActionData
```


运行时：


ActionController决定执行：

Attack01。


然后：

ActionPlayer播放：

Attack01_ActionData。


---

# 7. Cancel系统


# 7.1 Cancel定义


Cancel表示：

> 当前动作具有主动取消其他动作的能力。


Cancel属于取消方。


例如：


Action：

```
Dodge
```


拥有：

```
Cancel:

Dodge
```


表示：

Dodge可以取消拥有Dodge类型BeCancel的动作。


---

# 7.2 BeCancel定义


BeCancel表示：

> 当前动作允许被其他动作取消。


BeCancel属于被取消方。


例如：

Action：

```
Attack
```


拥有：

```
BeCancel:

Dodge
```


表示：

Attack可以被拥有Dodge类型Cancel的动作取消。


---

# 7.3 Cancel匹配规则


两个Action进行匹配：


取消方：


```
ActionA.Cancel.Tag
```


被取消方：


```
ActionB.BeCancel.Tag
```


匹配条件：


```
ActionA.Cancel.Tag

=

ActionB.BeCancel.Tag
```


成立：

ActionA可以取消ActionB。


---

# 8. Cancel Window


每个BeCancel拥有有效时间范围。


例如：

攻击动作：

播放时间：

0秒~1秒。


其中：

0.3秒~0.6秒允许被闪避取消。


BeCancel窗口数据：

包含：

- Tag
- StartTime
- EndTime


只有当前动作处于有效窗口：

取消关系才成立。


---

# 9. KeyCommand系统


每个Action可以绑定输入条件。


例如：


闪避：

```
Down + B
```


技能：

```
Down + Right + X
```


Input系统负责：

判断玩家是否完成输入。


成功后：

生成对应Action预约。


---

# 10. Reservation Action预约系统


# 10.1 设计目的


动作不会立即切换。


输入成功后：

创建ReservationAction。


加入ActionController预约列表。


用于解决：

- 输入提前量。
- 多动作竞争。
- 优先级判断。


---

# 10.2 ReservationAction数据


包含：

- 目标Action。
- Transition。
- 基础优先级。
- Transition优先级。
- 最终优先级。


---

# 11. ActionController系统


ActionController是运行时核心。


负责：

- 当前Action管理。
- Reservation列表维护。
- Cancel判断。
- 动作切换。
- 调用Transition。
- 调用ActionPlayer。


---

# 12. 动作切换流程


流程：

1. 玩家输入。

2. Input系统检测KeyCommand。

3. 找到满足条件的目标Action。

4. 创建ReservationAction。

5. 加入预约列表。

6. ActionController检查当前动作是否允许被取消。

7. 检查Cancel和BeCancel是否匹配。

8. 根据Priority选择动作。

9. 执行Transition。

10. ActionPlayer播放目标ActionData。


---

# 13. Priority系统


每个Action拥有基础优先级。


Transition拥有额外切换优先级。


最终优先级：


```
FinalPriority

=

ActionPriority

+

TransitionPriority

```


ActionController选择：

最终优先级最高的ReservationAction。


---

# 14. Transition系统


Transition表示：

两个Action之间的切换规则。


Transition属于：

Action之间的连接关系。


不是ActionData的一部分。


---

# 15. Transition数据


包含：


## From Action

被取消动作。


## To Action

执行取消动作。


## FadeOut

From Action退出时间。


## FadeIn

To Action进入时间。


## StartPercent

目标动画开始播放位置。


## Priority

该Transition额外优先级。

---

# 18. Edge连接系统


Edge表示：

两个Action之间存在取消关系。


连接方向：

```
被取消Action

        →

取消Action
```


例如：


```
Attack

        →

Dodge
```


表示：

Dodge可以取消Attack。


---

# 19. Edge自动生成规则


创建Edge：

自动生成：

From节点：

BeCancel。


To节点：

Cancel。


例如：

连接：

```
Attack → Dodge
```


生成：

Attack：

```
BeCancel:

Dodge
```


Dodge：

```
Cancel:

Dodge
```


---

# 20. Edge Transition配置


Edge保存TransitionData。

- FadeIn。
- StartPercent。
